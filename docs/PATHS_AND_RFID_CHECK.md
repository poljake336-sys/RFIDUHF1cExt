## 1. Пути на локальном ПК — повлияют ли на работу компоненты?

**Нет.** Путь `E:\RFIDUHF1cExt` и кириллица в `Users\Артем` важны **только при компиляции** на Windows (NDK/clang).

В `RFIDUHF.zip` попадает уже собранный код:
- `org_rfiduhf_addin.apk` + `.so` для ARM/ARM64/x86
- внутри — байткод/native, **без привязки к диску разработчика**

На ТСД 1С распаковывает макет во **внутреннее хранилище приложения** и грузит `.so`/`.apk` оттуда. DeviceAPI открывает UART устройства (`/dev/tty…`), а не файлы с вашего ПК.

Итого: zip универсален для любых машин/ТСД той же архитектуры Android. Пересобирать на каждой машине не нужно — нужен только актуальный `RFIDUHF.zip` в макете.

Сборка на ПК с кириллическим путём проекта — отдельная проблема разработчика; для этого рабочая копия лежит в `E:\RFIDUHF1cExt`.

## 2. Будет ли работать с RFID-метками? (глубокая проверка)

### Что совпадает с официальным Chainway uhf-uart-demo

| Шаг | Demo / DeviceAPI | Наша компонента |
|-----|------------------|-----------------|
| Синглтон | `RFIDWithUHFUART.getInstance()` | да |
| Открытие | `init(Context)` | да |
| Поток меток | `setInventoryCallback` + `startInventoryTag()` | да |
| Стоп | `stopInventory()` + callback=null | да |
| Закрытие | `free()` | да (shutdown / Done) |
| Данные | `UHFTAGInfo.getEPC/Tid/Rssi` | да → JSON TagRead |
| Мощность | `setPower(5..30)` | да |

Цепочка в 1С:

```
Курок/кнопка → НачатьИнвентаризацию
 → DeviceAPI callback (фон)
 → main thread
 → JNI onTagRead
 → ExternalEvent("org.rfiduhf.addin","TagRead", json)
 → ВнешнееСобытие в МП
```

### Что исправлено при этой проверке

1. **Гонка первых меток:** `inventoryRunning=true` ставится **до** `startInventoryTag()`, иначе первые EPC отбрасывались.
2. Sonar: имена полей/native, Exception вместо Throwable, lambda, `isEmpty()`, вынесен nested try.
3. JNI переименован в `onTagRead` / `onError` (согласовано Java↔C++).

### Что нельзя подтвердить без железа (честно)

Без физического C72 и меток в зоне антенны **нельзя** на 100% сказать «уже читает на вашем ТСД»:
- прошивка UART (`RFIDWithUHFUART` vs старый API)
- права доступа к serial в контексте сборки МП 1С
- частотный режим под регион (при необходимости `УстановитьЧастотныйРежим`)
- Keyboard Emulator курка vs кнопки формы в МП

Это не дыры в коде обёртки, а стандартные риски железа/прошивки. На эмуляторе/телефоне без UHF `Инициализировать()` закономерно вернёт Ложь.

### Минимальный смоук на C72

1. Загрузить `dist/RFIDUHF.zip` в макет.
2. `Инициализировать()` → Истина, `ОписаниеУстройства` содержит UHF_SW/HW.
3. Поднести метку, `НачатьИнвентаризацию()` → `ВнешнееСобытие` с EPC.
4. `Остановить` + `Завершить` → повторный init без reboot ТСД.

Если п.2–4 проходят — RFID-путь рабочий end-to-end.
